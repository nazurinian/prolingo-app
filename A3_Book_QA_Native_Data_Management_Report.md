## JSON and audio transfer

Workspace and nonempty Custom Collection JSON use `prolingo-text-pack` v1. The reader accepts compatible supported structured Text Pack v1 payloads with Text schema 1 or 2. A schema 1 payload is projected to persistent Units inside the v2 copy. Root, full Library and empty Custom Collection use the data-only `prolingo-book-library` v1 envelope with `textSchemaVersion: 2`, `audioBinaryIncluded: false`, UTC `exportedAt`, `scope` and ordered `packs`. Root entries are Workspace packs. Library uses Root Workspace packs followed by ordered Custom Collection packs. An empty Collection is admitted only inside the Book envelope. Unknown versions, invalid scopes, unsupported workspaces and invalid destinations fail closed. The envelope admits up to 1,000 packs and the file UI limits JSON to 16 MiB. Existing Text Pack readers can still open the ordinary Workspace and nonempty Collection downloads. [Book package implementation](src/domain/text/bookQaTransferDomain.js#L20) · [Text Pack validation and merge](src/domain/text/textPackJsonDomain.js#L102)

Import is additive and allocates new local UIDs. The native importer may retain a free source native ID and remaps collisions. Speaker references retain their workspace-local registry IDs and receive fresh global Speaker UIDs. Duplicate display names are permitted. Source UID lineage is retained for repeated copy/export with up to 32 prior aliases. Workspace or Collection content can be explicitly copied to Root, an existing Custom Collection or a newly created destination. Collection and Library structure can be recreated additively. UID-preserving attachment, source synchronization and replacement of the entire database remain gated because their authority and rollback semantics differ. JSON carries audio reference metadata. It does not install local binary proof, staged audio or trusted composition. Portable ZIP retains manifest v3, canonical RF/FULL filenames, exact byte verification and existing admission limits. Matching a remapped owner checks Workspace and owner lineage alongside recording compatibility. [Audio reference sanitization](src/domain/text/bookQaTransferDomain.js#L81) · [Source UID matching](src/domain/text/bookPortableAudioDomain.js#L124)

The browser fixture exported Workspace, Custom Collection, Root and Library JSON downloads and a Portable ZIP from the Book shell. A decoy occupied `DOC_000001` in the destination. The Workspace copy received `DOC_000002` and a distinct UID with source lineage preserved. JSON alone produced zero Ready audio bindings. The ZIP contained seven MP3s, one WAV, the v3 manifest and `AUDIO_INDEX.csv`. All eight imported runtime bindings matched their source SHA-256 digests, including the current EN/ID recordings, an alternate EN profile at +18% and +10 Hz, Heading audio and both Full assets. ZIP reimport created zero references and found all eight already available. Source generation used two local fixture-provider requests for headings and local MP3 fixtures for the body. The browser composed a Full Conversation WAV from verified inputs. Destination import verified composition compatibility and bytes without inheriting source-local trust.
